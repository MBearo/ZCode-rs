## 发现并修复

首轮主对话正常但侧栏显示 No tasks yet。Host task-index 在任务变为可见后调用既有 `readSession(existing-only)`，Rust 只提供 V4 查询而没有 `session/read`，因此索引回源返回 Unsupported method。

新增只读兼容投影，沿用唯一 Session owner，返回元数据、当前选型与模型能力、消息/工具及运行状态。读取不会触发请求、鉴权、resume 或修改 deliveryKind。导入保存 task kind 和归档时间，消息尾部裁剪与帧大小限制明确执行。V4 流和 Renderer 历史查询不变，不增加协议版本。legacy 逐消息 token/cost 目前为零占位；会话累计使用量保持真实事实。

新增真实 Host `readSession` 回归，并覆盖消息/工具、重启、读取无副作用、deliveryKind、messageLimit、导入附件/中断工具、任务种类/归档和模型错误状态的严格 schema 校验。先复现失败，再修复通过。

另外两项传输测试的裸子进程未隔离本机 TS 数据源，误触发历史导入并超过 5 秒 watchdog。补齐与 fixture 一致的配置/数据源隔离后通过，未放宽超时或删除退出断言。大型源库首次导入的取消延迟仍需专项验证，不能用隔离后的传输测试证明。

## 重现与边界

日常显式启用入口：`pnpm dev:desktop:rust --data-dir <实验目录>`，不传 `--config` 即使用 App 的 Provider 配置与账号。普通 `pnpm dev:desktop` 仍启动 TS。

本轮为连接自动化浏览器，直接使用相同 runtime override 启动 `scripts/dev-desktop-env.mjs production`，保留开发 CDP 端口；首次构建后以 `pnpm --filter @zcode/desktop dev:runtime` 重启。核心 override 为 `ZCODE_AGENT_SERVER_RUNTIME=rust-core`、`ZCODE_AGENT_SERVER_COMMAND=<绝对路径>/apps/zcode-rust/target/debug/zcode-rust`、`ZCODE_AGENT_SERVER_ARGS_JSON=["app-server","--stdio"]`。另以 `ZCODE_RUST_DATA_DIR` 与 `ZCODE_DESKTOP_*_DIR` 指向本次测试目录。启动包装本身没有通过浏览器绕过 Host 或直接调用内部 store。

仍观察到 `v4/conversation/workflowRuns` Unsupported method 警告，属于尚未实现的工作流能力；没有伪造空成功。当前对话/工具/队列场景未因此失败。手机、远程恢复、其他真实供应商协议、Windows/Linux 发行产物和大型旧库启动未在本轮验收。运行时间受真实供应商推理影响，本轮不构成 release 性能基准，也不替代 P1/P2 或证明全量替换。
