# Rust stdio 性能：与 Node 共用会话库之后

2026-09-25。M11.5 起 Rust 只读写 Node 的会话库（`~/.zcode/cli/db/db.sqlite`），冷加载从 Node 的消息与 part 重建模型上下文、界面行和快照状态（spec [rust-m11-node-storage](../specs/rust-m11-node-storage.md)）。本报告比较切换前后的 Rust release，并与 Node CLI 同负载对照。

机器：Apple M1 Max（10 核），macOS 15.7.7 / arm64，Node 24.14.0。测量期间机器上有与本任务无关的高负载进程（代理、抓包与系统媒体分析），load average 在 14–65 之间；各组都是交错运行、取五次中位数，比较前后差异可信，绝对值偏高。

## 本次修复

| 问题                                                                                                                | 修复                                                                                                                      | 结果                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 冷回放子代理行：每个子代理事件扫描全部行（Node `findSubagentLifecycleRow`），每次物化复制全部子代理行并线性查 child | 按行序维护子代理行位置索引；预期行借用快照或增量，只在摘要追加时复制；child 用位置表查找（语义与 Node 的 `Map.set` 相同） | 20,000 条消息、66,688 个 part 的压测会话：回放 12.2 s → 1.7 s（Node 同会话 1.5 s），冷读取合计 ≈ 4.4 s |
| 稳定分叉边界：每轮读取整段会话再定位（Node 同样）                                                                   | 只查消息 id 与边界消息本身，不读 part                                                                                     | 100 轮历史场景结束 RSS 回到切换前水平（修复前 60.2 MiB，现 49.2 MiB，切换前 49.1 MiB）                 |

## 固定负载：切换前后

基线为 M11.5 之前的 release（Rust 独立会话库），候选为当前 release。`node scripts/bench-zcode-cli-rust-suite.mjs <baseline> <candidate> <out> 256000 256000`，每个场景交错五次：

- stream：1 会话 × 8 轮 × 2048 chunks。
- history：1 会话 × 100 轮 × 64 chunks。
- sessions：4 会话 × 8 轮 × 512 chunks。

| --------------- | ----------- | ----------- | ----------- | --------------- | ------------ | -------------- | ------------ |
| 固定流式        | 15.0 → 22.5 | 33.2 → 34.3 | 284 → 285   | 1.76 → 1.61     | 49.9 → 50.6  | 6.15 → 3.18    | 2.29 → 1.51  |
| 100 轮历史      | 14.8 → 24.9 | 32.1 → 33.2 | 3323 → 3392 | 0.81 → 0.88     | 49.1 → 49.2  | 5.57 → 5.78    | 1.63 → 1.80  |

- 对话路径（首段、总耗时、RSS）变化在 4% 以内，属于该负载下的噪声量级。
- 存储：流式场景运行中占用减少 48%、持久文件减少 34%；100 轮历史的持久文件多 10%（Node 的 part 分行存储与索引）。
- 启动：该套件每次都用空目录，启动包含 Node 全部迁移（23 个，含表重建），多约 8–10 ms、空闲 RSS 多约 4.3 MiB。已有库时两版相同：`startup.mjs` 同一目录连续启动六次，首次（建库）17.5 MiB，其后 13.1–13.6 MiB、9–12 ms（切换前 12.7–13.1 MiB、8–11 ms）。迁移后执行 `pragma shrink_memory` 不能降低首次 RSS（内存留在分配器中），未采用。

## 大历史冷读取与驻留

`TSX_TSCONFIG_PATH=packages/services/tests/tsconfig.zcode-cli-rust.json node --import tsx scripts/bench-zcode-cli-rust-session-memory.mjs <a> <b> <out>`：12 个会话各 4 MiB 历史，依次冷读取，再保留一个订阅读其他会话；另有 200 条 × 32 KiB 的分页会话。切换前的基线不写 Node 库，无法用同一夹具播种，本次两端都用当前 release（A/A），给出绝对值：

| 指标，中位数           | 当前     |
| ---------------------- | -------- |
| 启动                   | 10.5 ms  |
| 依次读取后的 RSS       | 107 MiB  |
| 依次读取后的 footprint | 18.0 MiB |
| 保留订阅时的 footprint | 18.0 MiB |
| 冷读取 p95（4 MiB）    | 21.6 ms  |
| 大页 rowsRange         | 4.6 ms   |

- macOS 的 `ps` RSS 包含分配器已释放、标记为可复用的页；`footprint`（活动监视器的内存值）才是进程实际占用。循环冷读取三个会话 36 次，RSS 在约 27 次后停在 123 MiB，footprint 稳定在 15–17 MiB，没有泄漏。脚本现同时记录 `idleFootprintKiB` 与 `pinnedFootprintKiB`。
- 与 09-22 报告（Rust 独立库，RSS 38.7 MiB、冷读取 2.9 ms）相比，冷加载现在从 Node 的消息与 part 重建上下文、行与状态，瞬时分配更多，RSS 更高、冷读取更慢；09-22 没有记录 footprint，驻留内存无法直接对比，当前稳定在 15–18 MiB。
- 夹具调整：冷加载为每条 Node user 消息保留一份输入边界正文（编辑与重试用）。原夹具 64 条 64 KiB 的 user 消息使单个会话的估计驻留超过 16 MiB 空闲预算，读后立即被淘汰；现改为 1 条 user 与 64 条 64 KiB 的 assistant 消息。粘贴大段输入的会话因此不会留在空闲缓存中，下次读取重新冷加载；这是现有预算规则的结果，未改动。

## 用户真实库

`node --import tsx scripts/zcode-cli-rust-real-db-check.mjs`（在线备份副本，只输出计数与路径）：5,397 个会话、76,625 条消息，Rust 冷读取 p50 0.88 ms、p95 9.3 ms；最大值为上面的压测会话（与交互测试并行时 5.7 s，含比对导出额外的一次上下文重建）。全部会话与 Node 读取结果一致。

## 结论

- 切换到 Node 会话库后，对话路径性能不变，流式存储减少约一半；首次启动多一次建库迁移。
- 冷读取超大会话的二次方回放已修复，与 Node 同量级。
- 冷读取的瞬时分配比独立库时多，RSS 读数偏高，实际占用（footprint）约 18 MiB；进一步减少冷加载中间副本（hydrate、合成事件与行各一份）可单列优化。
