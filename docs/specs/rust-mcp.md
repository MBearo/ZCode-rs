# Rust MCP execution

Process termination uses an ownership snapshot. If a process exits between the snapshot and a signal, an OS signal failure is rechecked against a fresh snapshot: only an absent, zombie or identity-replaced target is considered already exited. A still-live owned target remains a fatal cleanup error. This rule also applies to the shared Bash process cleanup port.

MCP is part of the native Agent tool surface. Reuse the current `mcp/list` and create/resume `mcpServers` schemas without a wire-version change. Resolve enabled plugin servers plus workspace/user configuration; explicit Host servers override configured entries by name. Default isolation is session; only explicit workspace isolation shares a connection. Namespace tools using the TS sanitizer and reject namespace collisions. Discovery is paginated and bounded. Unknown/failed tools cannot silently execute another server's tool.

The native MCP adapter owns transports, connection pooling and private runtime configuration. Session actor owns input, tool rows, ordered canonical results, cancellation and durability. Tool definitions are prepared outside the actor before the model request; slow connection handshakes cannot block stop or unrelated RPCs. `mcp/list` connect runs as an auxiliary operation; status mode is observation only and never replaces connections. Revalidate explicit connect requests and close removed connections. Configuration secrets remain outside session transcripts and errors.

Use the official Rust MCP SDK for legacy initialize and modern discover negotiation, request correlation and cancellation. Bound stdio lines, HTTP/SSE events, tool counts and rendered results. MCP errors are tool failures; never transparently retry a call after dispatch, because it may have changed external state. A cancelled or timed-out request sends cancellation; stdio cancellation drains and reaps the owned process tree. Close/eviction/EOF releases session handles; workspace handles live until their last runtime consumer is released or explicit configuration removal. Cleanup failure stops execution.

Transport coverage includes stdio, Streamable HTTP and legacy SSE. OAuth and official plugin credential flows must use their existing authentication contracts; unsupported authorization must return an explicit failed status, never report connected or inject a guessed credential. Track any unimplemented authorization mode in the delivery report rather than treating a plain HTTP fixture as its validation.

Acceptance uses real Rust subprocesses and App schemas: stdio and HTTP discovery/call/error; separate same-name session servers and explicit workspace reuse; changed/removed configuration and status-only polling; cancellation before connection and during tool call; process cleanup, EOF, malformed/oversized output, pagination loops and namespace collisions; plugin/config switches and no secret-bearing error output. Persist model calls before tools and results before the next model step through the existing actor receipts.

Invalid persisted server entries are isolated as `failed/config_invalid` status; they must not prevent valid MCP servers or ordinary model requests from running. Explicit command payloads remain strictly validated before admission. Benchmark fixtures isolate HOME and XDG configuration so installed user plugins never affect deterministic measurements.

The HTTP client is initialized lazily when an HTTP/SSE server is actually connected and reused thereafter. Empty and stdio-only MCP configurations must not pay a second native certificate-store initialization on the first model request.
